## Telegram Inbox — обязательный протокол

Когда в чате появляется сообщение, начинающееся с `⚡ INBOX ALERT`, это push-уведомление от tgmcpd.

**Алгоритм — выполнять строго и полностью:**

1. **Заморозь** текущую задачу (запомни состояние, не теряй контекст).
2. **Прочитай** сообщения: вызови инструмент `inbox_read` — он вернёт список и автоматически подтвердит получение.
3. **Определи тип** каждого сообщения:
   - `стоп` / `отмена` / `не надо` → немедленно остановить задачу
   - уточнение или контекст → применить и продолжить
   - новое задание → завершить/отложить текущее, взять новое
4. **Ответь** в топик — вызови `send_message` с кратким подтверждением:
   - минимум: `«Получил. [одна фраза о том, что будешь делать]»`
   - если непонятно: задай уточняющий вопрос через `send_message`
5. **Действуй** согласно типу.

**Инструменты (MCP-сервер `tg-mcp-proxy`):**

| Инструмент | Когда вызывать |
|---|---|
| `inbox_read` | Сразу после получения INBOX ALERT — читает и ackует сообщения |
| `send_message` | Чтобы ответить пользователю в Telegram-топик |

**Нарушение протокола = баг.** Если не можешь ответить — напиши об этом через `send_message`.

## Git remotes — база и зеркало (BINDING)

- **База (источник правды): `origin` = GitHub** → `github.com/GG-QandV/Gate-MCPTG.git`
- **Зеркало: `gitgud`** → `ssh.gitgud.io:GGQandV/Gate-MCPTG.git`
- Upstream `main` = `origin/main`. Пуш: `git push origin main`, затем `git push gitgud main`.
- Проверка после пуша: `git rev-parse HEAD` = `git ls-remote origin main` = `git ls-remote gitgud main`.
- Если `git status -sb` показывает `...gitgud/main` — конфигурация неверна, исправить на `origin/main`.
